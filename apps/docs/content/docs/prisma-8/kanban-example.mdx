The kanban example is a complete SvelteKit app. Each user's boards live in IndexedDB in their browser and sync to a Postgres database on the server. Sign-in uses [better-auth](https://better-auth.com), with Google or an anonymous guest account.

- Live app: [next-kanban.prisma-idb.dev](https://next-kanban.prisma-idb.dev/)
- Source: [`apps/prisma-orm-kanban-example`](https://github.com/prisma-idb/prisma-idb/tree/main/apps/prisma-orm-kanban-example)

## What it shows

- **One schema for both databases.** `schema.prisma` feeds both the browser contract and the Postgres contract. better-auth's `Session`, `Account` and `Verification` models are marked `@@idb.exclude`, so they stay on the server. See [Client Contracts](/docs/prisma-8/sync/client-contracts).
- **Two migration histories.** `migrations/app` for IndexedDB and `migrations-postgres/app` for Postgres.
- **A managed sync client.** `createManagedAutoSyncIdbClient` gives one shared client that migrates, records changes for sync, and can be wiped on sign-out. See [Client](/docs/prisma-8/client#share-one-client-and-reset-it-on-logout).
- **Server-side authorization.** Push and pull endpoints use `createSyncServer` to check that every record belongs to the signed-in user. See [Server](/docs/prisma-8/sync/server).
- **Local writes that don't sync.** On first load, the app copies the signed-in user into IndexedDB with `withoutTracking`, since the server already has that row.
- **Sync status in the UI.** A badge shows how many changes are waiting to sync, updated from the `"outboxwrite"` event. The app syncs again when the browser comes back online.
- **A clean slate per account.** Sign-out calls `resetDb()`, so another account on the same browser starts with an empty database.
- **Offline use.** A small service worker caches the app shell, so the app opens without a network after the first visit. Changes made offline wait in the outbox and sync when the connection returns.

## Run it locally

You need Docker for Postgres. From the repository root:

```bash
pnpm --filter @prisma-idb/prisma-orm-kanban-example db:up     # start Postgres
pnpm --filter @prisma-idb/prisma-orm-kanban-example db:init   # create the tables
pnpm --filter @prisma-idb/prisma-orm-kanban-example dev
```

To check a production build:

```bash
pnpm --filter @prisma-idb/prisma-orm-kanban-example check
pnpm --filter @prisma-idb/prisma-orm-kanban-example build
pnpm --filter @prisma-idb/prisma-orm-kanban-example test:e2e
```

## Where to look

| File                                  | What it does                                         |
| ------------------------------------- | ---------------------------------------------------- |
| `src/lib/prisma/schema.prisma`        | The one schema for both databases.                   |
| `src/lib/prisma/db.ts`                | The managed sync client.                             |
| `src/lib/server/auth.ts`              | better-auth setup: Google and anonymous sign-in.     |
| `src/lib/server/sync.ts`              | `createSyncServer` and `createSqlSyncAdapter` setup. |
| `src/routes/api/sync/push/+server.ts` | The push endpoint.                                   |
| `src/routes/api/sync/pull/+server.ts` | The pull endpoint.                                   |
| `src/lib/stores/kanban.svelte.ts`     | Loads the workspace and runs the sync worker.        |
| `src/service-worker.ts`               | Caches the app shell and same-origin files.          |
| `static/manifest.webmanifest`         | Makes the app installable.                           |
