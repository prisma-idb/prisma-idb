The built-in HTTP sync now sends `BigInt` and `Bytes` values. Before, pushing an edit with a `bigint` threw before the request was sent, which stalled the outbox, and a `Uint8Array` reached the server as a numeric-keyed object. On the server, a pulled or rejected row with a `BigInt` or `Bytes` column made the response fail to serialize.

- **Breaking for custom transports:** `SyncRequestContext` has a new required `contract` property. TypeScript code that builds a context by hand and passes it to a push handler, such as `createSyncFetchHandlers(...).pushHandler(events, signal, { storageHash })`, no longer type-checks until it passes the client contract too. A handler that only receives the context from the worker needs no change. A custom push handler that serializes events itself must call the new `toWireEvent(context.contract, event)` before `JSON.stringify`.
- `createSyncFetchHandlers` encodes each event through the client contract's codecs: `BigInt` as a string, `Bytes` as base64 and `DateTime` as an ISO string. `toWireEvent` throws a `TypeError` when the contract is missing, instead of sending unencoded values, and a `WireEncodeError` when a codec can't encode the event, such as one holding an invalid date. A bulk delete's key range has its `lower` and `upper` bounds encoded as keys. `toWireEvent` also refuses, with a `WireEncodeError`, an event that still holds a `bigint`, `ArrayBuffer` or typed array after encoding, such as one for a model or field the contract no longer has, because `JSON.stringify` would throw on it or turn it into a numeric-keyed object. The fetch handlers fail only that event, with `retryable: false` and the error message, whether the encoder or `JSON.stringify` refuses it, and still send the rest of the batch.
- `createSqlSync` encodes the top-level `BigInt`, `Bytes` and `DateTime` columns of pulled records and of the records it returns with rejected pushes the same way, which is how it revives them. Fixing these responses, which failed to serialize before, is why `@prisma-idb/sync-server-sql` is a patch. If a rejected push's record can't be encoded, the push response still reports the applied results and omits that record. A pull page whose record can't be encoded fails with HTTP 500 and a message naming the changelog entry. A bulk delete's range key is refused by the server as a non-retryable `KEYPATH_VALIDATION_FAILURE`.
- `@prisma-idb/target-idb/runtime` exports `encodeJsonRecord` and `encodeJsonFieldValue`, the counterparts of `decodeJsonRecord`.
- `@prisma-idb/sync-extension-idb/client` exports `toWireEvent` and `WireEncodeError`.
