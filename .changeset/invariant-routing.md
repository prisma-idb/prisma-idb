Auto-migration picks each contract space's migration path the way upstream's extension-space apply path does. It takes the shortest path from the marker to the head whose migrations provide every invariant the head requires, and records the provided invariants on the marker. A space whose head requires an invariant no migration provides is refused with the missing invariant's name, before anything is applied. Before, the runtime compared hashes only, so a head's invariants were ignored, and when two migrations left the same contract it took one arbitrarily. Migrations planned by `prisma-idb` currently derive no invariants, so existing chains migrate as before. A bundle with two migration packages of the same name is refused. A database already at the head hash is refused when the head requires an invariant its marker lacks and no migration from the head provides it; for a generated app space, delete the local database or re-plan. The toolchain's migration graph modules are now bundled into `dist`, so the published client needs no extra dependency for them.
